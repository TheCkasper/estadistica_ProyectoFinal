CIBERSEGURIDAD // AUDITORÍA BANCARIA DISTRIBUCIÓN BINOMIAL : B(n=18, p=0.12)

1. Detección de vulnerabilidades en una auditoría de ciberseguridad

MUESTRA (n) 18 componentes
PROB. CRÍTICA (p) 12.00 % (0.12)
CRITERIO SUSPENSIÓN X ≥ 4 componentes
CONDICIÓN Independencia / Constante
ESPECIFICACIÓN DEL PROBLEMA

Una empresa especializada en ciberseguridad realiza auditorías sobre aplicaciones web utilizadas por instituciones financieras. Durante una evaluación, los analistas seleccionan aleatoriamente 18 componentes de software. Según los registros históricos, cada componente tiene una probabilidad del 12 % de presentar una vulnerabilidad crítica. Para este análisis se supone que las condiciones de los componentes son independientes y que la probabilidad de encontrar una vulnerabilidad es constante. La política de seguridad establece que, si se detectan 4 o más componentes vulnerables, deberá suspenderse temporalmente la liberación del sistema.

2. Recuperación de paquetes en una red de comunicaciones

ÉXITOS OBJETIVO (r) 5 paquetes OK
PROB. TRANSMISIÓN (p) 75.00 % (0.75)
LÍMITE MÁXIMO 8 intentos máx
SLA CONFIABILIDAD ≥ 95.00 %
ESPECIFICACIÓN DEL PROBLEMA

Una empresa de telecomunicaciones está evaluando un protocolo de recuperación de paquetes de datos. Cuando se detecta un paquete corrupto, el sistema solicita su retransmisión. Cada intento tiene una probabilidad del 75 % de completarse correctamente, de manera independiente. Para restablecer una comunicación, el protocolo necesita obtener 5 retransmisiones exitosas. El sistema cuenta con una política que permite realizar un máximo de 8 intentos antes de activar un mecanismo alternativo de recuperación.

3. Monitoreo de incidentes en un centro de operaciones de seguridad

TASA BASE 9 alertas / 15 min
TASA EN 20 MIN (λ) 12.00 alertas
UMBRAL RIESGO > 15 alertas / 20 min
LÍMITE FALSA ALARMA < 5.00 %
ESPECIFICACIÓN DEL PROBLEMA

Un Centro de Operaciones de Seguridad (SOC) monitorea la infraestructura tecnológica de una organización. Los registros indican que se producen, en promedio, 9 alertas de seguridad cada 15 minutos. Se supone que las alertas ocurren independientemente y con una tasa promedio constante durante el período estudiado. El sistema de monitoreo considera que existe una posible situación de riesgo elevado cuando se registran más de 15 alertas durante 20 minutos.

CLOUD COMPUTING // ALTA DISPONIBILIDAD DISTRIBUCIÓN BINOMIAL : B(n=20, p=0.08)

4. Disponibilidad de servidores en una infraestructura de nube

TOTAL SERVIDORES 20 virtuales
PROB. FALLA (p) 8.00 % por ventana
TOLERANCIA REDUNDANCIA Falla ≤ 3 servidores
SLA DISPONIBILIDAD ≥ 95.00 %
ESPECIFICACIÓN DEL PROBLEMA

Una empresa de servicios tecnológicos administra una plataforma de comercio electrónico mediante una infraestructura de 20 servidores virtuales. Durante las pruebas de disponibilidad, el departamento de operaciones ha determinado que cada servidor tiene una probabilidad del 8 % de presentar una falla durante una ventana de mantenimiento de dos horas. Para efectos del análisis, se considera que las fallas de los servidores ocurren de manera independiente y que todos tienen la misma probabilidad de fallar. El sistema cuenta con mecanismos de redundancia que permiten mantener la operación normal siempre que no fallen más de 3 servidores durante esa ventana.

El servidor dispone de un mecanismo de protección que genera una alerta cuando recibe más de 10 solicitudes en un minuto.

REDES & SISTEMAS DISTRIBUIDOS // COLAS DE EVENTOS DISTRIBUCIÓN EXPONENCIAL : λ = 0.20 msg/seg

7. Tiempo de espera en un sistema de mensajería asíncrona

TASA DE ENTRADA 12 msg / minuto
TASA EN SEGUNDOS (λ) 0.20 mensajes/seg
TIEMPO PROMEDIO (1/λ) 5.00 segundos
UMBRAL TIMEOUT > 15 segundos
ESPECIFICACIÓN DEL PROBLEMA

Una empresa de logística utiliza una arquitectura de microservicios para procesar mensajes relacionados con pedidos, entregas y actualizaciones de inventario. Durante las horas de operación, un servicio recibe en promedio 12 mensajes por minuto. Para el análisis, se supone que los mensajes llegan siguiendo un proceso con tasa constante e independiente. El equipo de monitoreo está interesado en el tiempo transcurrido desde un instante de observación hasta la llegada del siguiente mensaje, debido a que ciertos procesos dependen de la recepción de nuevos eventos.

BASES DE DATOS & OPTIMIZACIÓN // QUERY PROFILING DISTRIBUCIÓN NORMAL : N(μ=240ms, σ=35ms)

8. Evaluación del rendimiento y SLA de una base de datos

TIEMPO MEDIO (μ) 240.00 ms
DESVIACIÓN ESTÁNDAR (σ) 35.00 ms
REQUISITO SLA ≤ 300 ms en ≥ 95%
TEST ALTERNATIVO μ=220ms, σ=55ms
ESPECIFICACIÓN DEL PROBLEMA

Una institución financiera implementó una nueva base de datos para procesar consultas relacionadas con movimientos y transacciones. Después de ejecutar pruebas de rendimiento, el equipo de ingeniería determinó que los tiempos de respuesta individuales pueden aproximarse mediante una distribución normal, con los siguientes parámetros: Tiempo promedio 240 ms, Desviación estándar 35 ms. El contrato de nivel de servicio (SLA) establece que al menos el 95 % de las consultas debe responder en 300 milisegundos o menos.
